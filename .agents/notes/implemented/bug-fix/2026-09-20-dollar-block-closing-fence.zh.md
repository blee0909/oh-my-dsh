# Agent Note: 美元数学块收尾围栏

Status: implemented

[English](2026-09-20-dollar-block-closing-fence.md) | 中文

## 问题

助手回复以模型编写的文本进入结算版 Markdown grammar，而写成 `$$` 块的展示公式通常把收尾围栏放在最后一个内容行上。上游 `micromark-extension-math` 只在一行以 `$$` 开头时才算闭合，并把开行的剩余内容读作 `mathFlowFenceMeta` token，由 `mdast-util-math` 存为该 math 节点的 `meta`——本渲染器从不读取该字段。于是这种写法在任何位置都没有收尾围栏：调用处把本扩展声明在上游 `math()` 之前，而 micromark 会先尝试后注册扩展的构造，因此上游 flow 构造接管该块并把输入一路消费到文档结尾，回复剩余部分整体变成一个 `math` 节点。KaTeX 拒绝该节点，`renderTexToReact` 退回 `katex-error` span，被消费掉的剩余内容再也不会按 Markdown 解析，于是回复丢掉公式开头那一行，并把其后的所有内容显示为源码原文。

## 决策

[`mathCompatibility.ts`](../../../../packages/client/ui-primitives/src/markdown/mathCompatibility.ts) 拥有 `$$` 块形式，[`parse.ts`](../../../../packages/client/ui-primitives/src/markdown/parse.ts) 注册该扩展而不再注册上游 `math()`。

美元 flow 构造会跨非惰性换行继续，因此围栏在块的任意内容行末尾都能闭合；收尾围栏至少需要两个 `$` 且可以重复，而上游反而要求收尾 run 不短于开围栏；更长的开围栏只有在它结束该行时才算块围栏，于是上游的行内 `$$$…$$$` 文本数学仍可用；开行剩余内容保留为公式内容，而不是变成 `mathFlowFenceMeta`；没有收尾围栏的块会让构造失败，于是保留原文而不是生成数学节点。

收尾围栏尝试若在某行行首遇到围栏，构造同样失败：`$$` 块不能嵌套，而把该围栏当作内容会在之后每次尝试中重新扫描到文档结尾。行中的 `$$` 保留为内容，因为公式本身会包含它；而该快速失败必须在每个延续行上都成立——包括以奇数反斜杠 run 结束的行，否则被延续的该标志会跳过下一行的收尾围栏尝试，从而也跳过快速失败。

该扩展携带上游的行内美元 `mathText` 构造，而不携带上游的美元 `mathFlow` 构造，因此 `$$` 只有一个构造负责，行内 `$…$` 仍保持上游行为。

如果第一次结算解析在某个拒绝的定界符位置留下原文段落，`parse.ts` 会记录该源偏移，并只在该位置用非 concrete fallback 重试。未闭合块后的列表和引用块于是交给普通 flow grammar 解析，同时其他位置的有效数学块继续使用 concrete 构造。

## 备选方案

**保留上游 `$$` flow 构造、修好得到的数学节点。** 否决：缺陷是解析期结果。构造一旦消费掉回复，渲染端任何修补都无法恢复 Markdown 结构或被丢掉的开行。

**保留只支持同行的美元形式，改为给消费设上界。** 否决：这样做既不能渲染报告中的写法，而没有归属的上界仍会把块交给那个消费整篇文档的构造。

**在调用处注册上游 `math()`，只去掉它的美元 flow。** 否决：micromark 会把后注册扩展的构造拼接到先注册扩展之前，调用方可能弄错的注册顺序本身就是缺陷；兼容扩展改为拥有自己新增的定界符。

## 后果

收益：收尾围栏写法能渲染为展示公式，没有收尾围栏的块降级为原文，错误定界符不再生成一个巨大的数学节点。回归测试把 6,000 个重复的未闭合块保留为普通段落且不输出 KaTeX；该检查的耗时不属于产品契约。

代价：开行上的上游 info string（`$$asciimath`）现在是公式内容，而不再是 `node.meta`；本渲染器从不读取 `meta`。另外，开行带内容的长围栏（`$$$x`，随后内容，再 `$$$`）会渲染为行内文本数学而不是展示块，而上游是丢掉该行文字后渲染为展示块。

未变：数学开头失败后，标题、表格和代码围栏仍按普通 Markdown 解析。fallback 现在也会重新解析其后的列表和引用块，不再把围栏标记留在段落中。
